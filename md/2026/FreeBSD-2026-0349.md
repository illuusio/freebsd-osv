# Erlang/OTP -- relative path traversal in the zip module
The Erlang/OTP team reports:

> Fixed a bug where zip:unzip/1,2 and zip:extract/1,2 were vulnerable to
> a relative path traversal attack. A crafted zip archive containing
> entry names such as ../x/y could have caused files to be written
> outside the intended extraction directory.


## Affected packages
 - **erlang**
    - **Fixed:** 28.5.0.4,4
 - **erlang-runtime27**
    - **Fixed:** 27.3.4.15
 - **erlang-runtime28**
    - **Fixed:** 28.5.0.4
 - **erlang-runtime29**
    - **Fixed:** 29.0.4
