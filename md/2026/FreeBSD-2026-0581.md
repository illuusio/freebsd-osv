# LibreSSL -- Multiple OCSP client vulnerabilities
VulnCheck reports:

> CVE-2026-118371: LibreSSL through 4.4.0 contains a CRLF injection
> vulnerability in the libcrypto OCSP_sendreq_new() and OCSP_parse_url()
> functions, which write unvalidated request paths into the OCSP POST
> request line. Attackers can embed carriage return and line feed
> characters in a certificate\'s Authority Information Access OCSP URI
> to inject HTTP headers or split requests sent to responders and
> proxies.
>
> CVE-2026-118372: LibreSSL ocspcheck through 4.4.0 contains a CRLF
> injection vulnerability that allows attackers to inject HTTP headers
> by embedding CR/LF sequences in a certificate\'s AIA OCSP URI path.
> Because url2host() copies the path without rejecting control
> characters and http_open() places it in the POST request line,
> attackers can inject headers or split OCSP requests sent to the
> responder host.
>
> CVE-2026-118373: LibreSSL ocspcheck through 4.4.0 contains a cleartext
> transmission vulnerability because url2host() discards the OCSP URL
> scheme and http_alloc() only selects TLS for port 443. On-path network
> attackers can read OCSP requests sent to https responder URLs on
> non-443 ports, exposing certificate serial numbers, issuer hashes, and
> nonces.
>
> CVE-2026-118374: LibreSSL ocspcheck through 4.4.0 contains a memory
> exhaustion vulnerability that allows malicious OCSP responders to
> exhaust memory by sending unbounded HTTP responses. Attackers
> controlling the responder or intercepting plain HTTP AIA OCSP traffic
> can stream endless headers or body data to http_head_read() and
> http_body_read(), denying certificate status checks.
