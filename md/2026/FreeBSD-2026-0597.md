# security/wolfssh -- multiple vulnerabilities
wolfSSL reports:

> - CVE-2026-16516 (Critical): wolfSSH did not check that the ECDSA
>   curve in a server\'s host key blob matched the negotiated algorithm,
>   so a man-in-the-middle could substitute a key on another curve and
>   pass verification with a private key of its own. Also requires a lax
>   public key check callback.
> - CVE-2026-83540 (High): wolfSSHd on Windows shared one authentication
>   context, and the logon token stored in it, across concurrent
>   connections, so a user with a valid account could end up logged in
>   as another, more privileged user.
> - CVE-2026-84897 (Medium): A wolfSSH server accepted the DH group
>   exchange messages only a server sends from an unauthenticated
>   client, which made the server run the client-side handler and
>   primality-test an attacker-chosen group of up to 8192 bits.
> - CVE-2026-81535 (Medium): With \--enable-fwd, forwarded-tcpip channel
>   opens were admitted without consulting the forwarding policy
>   callback, so a peer could make an endpoint allocate buffers for
>   forwarding channels the application never authorized.
> - CVE-2026-83742 (Medium): wolfSSH_RealPath() bounded each path
>   component by the space left in the output buffer rather than by the
>   buffer\'s size, so a crafted SFTP path could write a single
>   terminating NUL one byte past the end of a stack buffer.
