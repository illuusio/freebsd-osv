# Roundcube -- Multiple vulnerabilities
The Roundcube Mail project reports:

> - IMAP command injection via CRLF in \_uid parameter of mail/headers
>   and mail/viewsource action
> - bug where an alias login wasn't qualified by IMAP host
> - Add a size limit to the CSS proxy content processing
> - SSRF filter (is_local_url()) bypass via NAT64 64:ff9b::/96
> - remote content blocking bypass via SVG SMIL by attribute
> - remote content blocking bypass via CSS escapes in FuncIRI attributes
>   (again)
> - passing potentally unsafe attachment content into ImageMagick on
>   image resize
> - mail header injection via the From display-name in the Bounce
>   (resend) action
> - mail header injection via References/In-Reply-To/Message-ID/From
>   parameters
> - object injection primitive in rcube_session::unserialize() via
>   "!"-prefixed session keys
> - ImageMagick resource limits bypass by GD fallback during thumbnail
>   generation
> - CSS scoping bypass in HTML messages using at-rules
> - bug where deprecated action aliases bypassed disabled_actions
>   setting
> - IMAP command injection via CRLF in \_flag parameter of mail/mark
>   action
> - CSRF validation bypass in the mark-as-junk action
> - XSS issue in handling of password driver error responses
> - mail header injection via subject of a message forwarded as
>   attachment
> - mail header injection via media type in an inline image data URI
> - bug where Password Modoboa driver could change password for another
>   account
> - unsafe use of a login name in SquirrelMail import file path
