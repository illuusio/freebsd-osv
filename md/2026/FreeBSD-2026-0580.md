# amule -- multiple vulnerabilities
aMule developers report:

> A security release first: it fixes 15 vulnerabilities reported through
> GitHub Security Advisories, and 11 of them are also present in aMule
> 2.3.3. If you still run 2.3.x or any 3.x release, please upgrade.
>
> - GHSA-cp82-q55r-936c (High): heap off-by-one write and use-after-free
>   in the UPnP control point, reachable from the local network when
>   UPnP is enabled.
> - GHSA-2crf-cv3v-53w5 (High): unbounded EC tag nesting crashes amuled
>   before authentication.
> - GHSA-52mv-r67q-c985 (High): a single Kad search request can block
>   the main thread for tens of seconds.
> - GHSA-q2jr-xf54-v364 (High): a remote-control user can move files
>   anywhere on the host.
> - GHSA-3j74-m5qw-75xg (High): EC-settable ffprobe path leads to
>   execution of arbitrary binaries.
> - GHSA-cvxg-rcqx-rp9p (Medium): heap memory disclosure to eD2k peers.
> - GHSA-g22c-pmwf-qmwm (Medium): peer-supplied OS info used as a format
>   string in the statistics tree.
> - GHSA-6qxf-6fj4-q8fv (Medium): unchecked EC tag types leak heap bytes
>   into the log before authentication.
> - GHSA-hv8p-rp6f-rmf7 (Medium): memory exhaustion triggered by an
>   upload source.
> - GHSA-vh6g-8m3v-wfmf (Medium): amuleweb guests can add downloads and
>   make the core fetch arbitrary URLs.
> - GHSA-42j9-4vh7-jvw6 (Medium): malicious update files can fill the
>   disk or crash aMule.
> - GHSA-7rxg-6w2f-3w57 (Medium): multi-part downloads can complete
>   without MD4 verification.
> - GHSA-frfq-582f-4jww (Medium): server list URLs fetched without
>   protocol restriction allow SSRF via gopher://.
> - GHSA-gc7p-357m-xj2j (Low): synchronous EC clients accept cleartext
>   replies on an encrypted session.
> - GHSA-vj9g-4mg6-q9hw (Low): cross-port request forgery against
>   amuleapi.


## Affected packages
 - **amule**
    - **Fixed:** 3.2.0
