# FreeBSD -- Remote DoS via receive-side kernel TLS
# Problem Description:

TLS 1.3 embeds the actual record type as the last non-zero byte of the
decrypted payload, optionally followed by zero padding. The code which
searches for the inner record type had an off-by-one bug which could be
triggered by an invalid frame, leading to an underflow followed by an
unconditional NULL pointer dereference, causing a kernel panic.

# Impact:

A remote TLS 1.3 peer can send a specially crafted record to trigger a
kernel panic, resulting in a Denial of Service (DoS).
